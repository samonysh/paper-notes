# 可视化笔记规范

## 1. 最终交付格式

最终产物必须以一个 UTF-8 Markdown 文档为唯一阅读入口。所有正文、摘要、前置学习路径、概念解释、证据索引、关联论文、图表解读和附录内容都整合进该文档；不得把这些内容拆成额外的 Markdown、HTML 或网页附件。

图像是单文档规则的唯一外部资产例外：统一放在主文档同级的 figures/ 目录，并使用相对路径嵌入。最终 Markdown 只能嵌入 .svg 或 .png，不得链接 .html、Mermaid 源码、ASCII 图、临时截图或不可预览的编辑源文件。

~~~markdown
![目标论文从研究问题、输入数据、核心机制到评价与结论的整体研究架构。](figures/short-title--research-architecture.svg)

*图 1：整体研究架构。根据论文 §3–§5 与 Fig. 2 整理；分组和连接关系属于分析性重构。*
~~~

默认优先 SVG，以便无损缩放和保留可访问性信息；目标阅读器不稳定支持 SVG、原图属于位图或需要像素级复现时使用 PNG。若同时生成两种格式，只在 Markdown 中嵌入一种，避免重复。

## 2. 强制的整体研究架构图

每份基于可访问全文生成的完整笔记都必须包含一张“整体研究架构图”。该图不是装饰性目录，而要让读者一次看清论文的研究问题、关键输入或证据、方法或综合机制、评价路径、核心发现以及边界之间的关系。

- **研究论文**：优先表现“问题/假设 → 数据或材料 → 方法与关键机制 → 实验/验证 → 主要结果 → 适用边界”。
- **综述论文**：优先表现“范围与研究问题 → 检索/纳排或来源范围 → 分类轴/综合机制 → 共识与争议 → 缺口与议程”。
- **理论论文**：优先表现“问题与假设 → 定义/公理 → 关键命题或证明依赖 → 推论 → 适用条件”。
- **系统或工程论文**：优先表现“需求 → 系统组件/数据流 → 核心接口或训练推理流程 → 评价环境 → 结果与失效模式”。

如果只能访问摘要或元数据，无法可靠恢复整体研究关系，则不得补图凑数；在应出现图的位置写明“全文证据不足，未生成整体研究架构图”，并说明缺失材料。

## 3. 使用 diagram-design 构图

整体研究架构图和其他分析性图示必须使用已安装的 diagram-design skill。绘制前执行其风格门控，并读取适用的类型参考和语义模式参考。

整体研究架构图默认参数：

| 决策 | 默认值 | 调整条件 |
|---|---|---|
| 类型 | Architecture；以时间/步骤为主时可用 Process 或 Data flow | 根据论文主导关系选择，不混用两套布局语法 |
| 尺寸 | doc-wide | 内容简单时可用 doc-inline |
| 细节 | balanced | 超出复杂度预算时保留一张总览图并在正文展开 |
| 受众 | mixed | 用户明确要求工程或管理视角时调整 |
| 最终格式 | SVG | 阅读器兼容性或位图内容要求时改为 PNG |

diagram-design 生成的自包含 HTML 只是中间产物。随后必须按其 references/export.md 导出图示节点为 SVG 或 PNG，再把导出文件嵌入 Markdown；中间 HTML 不属于最终交付物。SVG 必须保留 title、desc、role="img" 和可解析的 aria-labelledby；PNG 必须配有准确的 Markdown 替代文本。

每张分析性图都要满足：

1. 只呈现可由论文证据或明确标注的分析综合支持的关系；
2. 图题后注明依据的章节、页码、公式、表格或原图；
3. 区分“作者原有结构”和“笔记作者重构”；
4. 不虚构接口、因果方向、阶段、数值或分类层级；
5. 图前用短文说明读图问题，图后解释主线、例外和不能推出的结论；
6. 通过 diagram-design 的自检与几何检查后再导出。

## 4. 论文研究图常用布局

可以参考公开科研绘图模板的结构规律，但只能借鉴信息组织方式，不复制其画面、配色、图标或受保护素材：

- [通用科研课题研究技术路线图](https://sci.cengxuyuan.cn/template/research-methodology-flowchart-template/)：用“研究流程—研究内容—研究方法”的对应关系组织复杂项目；
- [学位论文研究技术路线图](https://sci.cengxuyuan.cn/template/phd-research-technical-route-framework/)：用自上而下的“背景—理论—实证—模型—建议—结论”串联整篇研究；
- [科研项目技术路线框架图](https://sci.cengxuyuan.cn/template/research-technical-route-framework/)：用“研究现状—技术路线—研究基础”形成模块化分层；
- [数字素养与乡村建设多维框架](https://sci.cengxuyuan.cn/template/digital-rural-framework-structure/)：适合“中心机制—外围主题—顶层驱动—底层支撑”的多维理论框架；
- [数字医疗与创新机制研究框架](https://sci.cengxuyuan.cn/template/research-policy-innovation-framework/)：适合纵向“背景—现状—机制—案例—评估—建议”的社会科学或政策研究。

选择布局时以目标论文的真实论证结构为准。若三列表格已经更清楚，就不要采用三列式画法；仍需保留一张更简洁的整体研究架构总览，并把细节留在 Markdown 表格中。

## 5. 其他可选图示

整体架构图以外，只有当图示明显优于文字或表格时才增加。完整笔记通常再使用 0–4 张高价值图示。

| 论文类型 | 图示内容 | diagram-design 类型 | 注意事项 |
|---|---|---|---|
| 研究论文 | 实验或数据流程 | Flowchart / Timeline / Process | 不得暗示未报告的控制条件 |
| 研究论文 | 结果比较 | Bar / Line / Scatter / Radar | 只重绘含义和数值均明确的数据 |
| 研究论文 | 局限与失效模式 | Fishbone / Quadrant / Layer stack | 区分作者报告与分析判断 |
| 综述论文 | 领域知识地图 | Tree / Nested / Layer stack | 避免庞大的引用网络 |
| 综述论文 | 领域演化 | Timeline | 标注有争议的阶段划分 |
| 综述论文 | 证据筛选 | Flowchart | 不得虚构 PRISMA 数量 |
| 综述论文 | 技术/应用比较 | Quadrant / Radar / Bar | 比较轴薄弱时改用表格 |
| 综述论文 | 缺口与研究议程 | Process / Gantt / Fishbone | 明确标注为笔记综合 |

数值图必须说明指标方向、单位、数据集或任务、比较基线和原始位置。不得把估读或 OCR 不确定的值绘制成精确图形。

## 6. 摘录论文原图或原表

在合法获得全文且摘录能显著降低理解门槛时，可以把少量论文原图或原表以 PNG/SVG 嵌入笔记，但这不是完整笔记的数量要求。

优先顺序：

1. 论文或补充材料提供的可复用 SVG/PNG，并且许可证允许；
2. 从用户提供或公开合法 PDF 中提取嵌入图像；
3. 仅裁剪理解核心论证所必需的图表区域；
4. 权利或清晰度不适合摘录时，只链接和解读原位置，或基于明确数据制作分析性重绘。

每个摘录必须：

- 标明“论文原图摘录”或“论文原表摘录”，不得冒充自制图；
- 给出原始编号、PDF 页码、章节、规范 URL/DOI、访问日期和许可证（若可得）；
- 保留图例、坐标轴、单位和会改变解释的注释；只裁掉无关页边，不得改变数据或移除水印、署名与版权信息；
- 在图前后解释为什么摘录、它支持什么、不能推出什么；
- 使用描述内容的文件名，例如 figures/short-title--original-fig-3.png；
- 控制数量和分辨率，只摘录评论所必需的部分，不批量复制论文全部图表。

若许可证或使用边界不明确，应优先链接原图位置并进行文字解读；不得绕过付费墙、访问控制或数字版权管理来获取图片。

## 7. 最终检查

- [ ] 最终只有一个 Markdown 阅读入口，所有文字性附录已合并其中。
- [ ] Markdown 中所有图像路径均为相对路径，扩展名仅为 .svg 或 .png。
- [ ] 完整全文笔记包含整体研究架构图，或明确说明为何证据不足而未生成。
- [ ] 架构图由 diagram-design 构建并按其导出规范生成 SVG/PNG。
- [ ] 每张图都有替代文本、标题、证据锚点和“作者结构/分析重构”标记。
- [ ] 原图摘录具有原始编号、页码、来源和许可证信息（若可得）。
- [ ] 没有把不确定关系、OCR 估值或分析判断伪装为论文事实。
- [ ] 中间 HTML、编辑源文件和临时截图未作为最终 Markdown 的依赖。
